# v1.0.3

## Release notes

- Add TypeSafe to the provider roster using its official Better Stack JSON feed at https://status.typesafe.ai/index.json.
- Increase the roster to 57 companies. TypeSafe is off by default and can be enabled in settings.
- Preserve legacy `disabledIds` selections against the pre-v1.0.3 roster so upgrades do not silently enable TypeSafe or future providers.
- Reuse the existing aggregate-status parser, without new dependencies or parser changes. Resolved incidents and historical downtime do not trigger an alarm.

- Avoid false red alerts when the shell starts before networking. Initial unavailable checks show “Connecting…” for up to 30 seconds, with retries five seconds after each failed attempt. Successful checks end this window early; confirmed provider outages remain red throughout.
- Retry unavailable checks when the panel opens. Persistent failures and failures after the startup window remain visible.

## Verification

```sh
python -m unittest discover -s tests
node --test tests/*.test.mjs
python tests/check-panel-runtime.py
python tests/check-startup-runtime.py
./fetch-status fetch --enabled typesafe
git diff --check
```

`tests/fixtures/typesafe-operational.json` is a full public response captured from the official JSON endpoint on 2026-09-22. Tests use synthetic aggregate-state variants for outage and maintenance cases; those variants are not records of live outages.

## Publish after merge

1. Merge the provider PR into `main` and repeat the verification commands against the merged commit. Confirm that the live fetch returns a TypeSafe result with no `error`; its status may legitimately change.
2. Create the `v1.0.3` tag and GitHub release on that verified commit, using the release notes above.
3. Read `git rev-parse HEAD` on current `main`. Submit the full 40-character commit SHA using the marketplace's [Plugin verification form](https://github.com/omacom/omarchy-plugin-marketplace/issues/new?template=verify-plugin.yml):
   - Verification action: `Verify and publish a newer upstream commit`
   - Plugin ID: `io.github.ollieedgeley.ai-frontier-status`
   - Repository URL: `https://github.com/ollieedgeley/ai-frontier-status`
   - Target commit: the verified merged commit, not the PR branch or a placeholder.
4. Review the marketplace compatibility and Automated Security Baseline reports. A marketplace maintainer must apply `approved-and-verified` to promote the exact snapshot.
5. Read back the marketplace listing and confirm version `1.0.3` and the intended commit before reporting publication complete.

Do not create a duplicate initial plugin submission. Existing marketplace snapshots remain unchanged while an update awaits approval. See the marketplace's [update instructions](https://github.com/omacom/omarchy-plugin-marketplace/blob/main/SUBMISSION.md#update-an-existing-listing).

## Recovery

Before merge, close the PR without changing the published version. After merge, revert the provider change if needed; leave published release tags intact and prepare a subsequent patch version. Marketplace promotion requires a separate exact-commit review.
